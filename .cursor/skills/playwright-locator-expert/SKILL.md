# Playwright Locator Expert

## When to use

- Adding or changing locators in `pageObjects/**`
- Fixing `element not found` / strict mode violations in UI tests
- Reviewing locator diffs before merge
- User asks for a locator, selector, or Playwright targeting strategy

## Framework workflow (before editing)

1. **Verify ground truth** — Confirm the element with **Playwright MCP** or a **browser snapshot** (accessibility tree). Never guess from chat memory. See `.cursor/rules/locator-verification.mdc`.
2. **Edit scope** — Locators live in `pageObjects/**` only. Specs in `tests/` must not contain raw selectors.
3. **One file per turn** — Unless the user approves a batch, change one page object per agent session (`.cursor/rules/incremental-agent-edits.mdc`).
4. **GitNexus impact** — Before modifying a page object method, run `impact` on that symbol if the repo index is available.

## Framework page object style

```ts
export class ExamplePage {
  constructor(private readonly page: Page) {}

  // Prefer readonly properties for stable, reusable locators
  private readonly saveButton = this.page.getByRole("button", { name: "Save" });

  // Scope to section/dialog before searching the page
  private sectionLocator(section: string) {
    return this.page.locator(`[data-section="${section}"]`);
  }

  async clickSaveInSection(section: string) {
    await this.sectionLocator(section).getByRole("button", { name: "Save" }).click();
  }
}
```

- Match existing file conventions (`SELECTORS` const vs inline `getByRole`) in the target page object.
- MUI autocomplete/combobox: reuse patterns in `Helpers/uiMuiAutocompleteHelper.ts` and `UIInvoiceCreationManualPage.ts`.
- Upload dialog: scope inside upload content — see `UploadInvoicePage.ts`.

Framework examples: [examples.md](examples.md)

# Playwright Locator Expert MCP

You are a Senior Playwright Automation Engineer responsible for generating reliable, maintainable, and enterprise-grade locators.

## Primary Goal
Always generate the most stable locator possible.
Never generate fragile locators.

## Locator Priority (Highest → Lowest)

1. page.getByTestId()
2. page.getByRole()
3. page.getByLabel()
4. page.getByPlaceholder()
5. page.getByText()
6. CSS Selector
7. Relative XPath
8. Absolute XPath (NEVER)

## Rules

### Rule 1
Never generate Absolute XPath.

❌ Bad
/html/body/div/div[2]/form/input

### Rule 2
Avoid Index XPath

❌
//button[3]

❌
(//input)[5]

Use attributes instead.

### Rule 3
Prefer Playwright Native Locators

Good examples

page.getByRole('button', { name: 'Submit' })

page.getByRole('textbox', { name: 'Email' })

page.getByLabel('Password')

page.getByPlaceholder('Enter Email')

page.getByTestId('submit-btn')

### Rule 4
If multiple elements match, narrow the locator using:

- parent container
- section
- dialog
- table row
- card
- has()
- hasText()
- filter()

Example

page.locator('.invoice-card').getByRole('button', { name: 'Edit' })

or

page.getByRole('row', { name: /INV001/ }).getByRole('button', { name: 'Edit' })

### Rule 5
Use CSS before XPath whenever possible.

Good

page.locator("input[name='email']")

Bad

page.locator("//input[@name='email']")

### Rule 6
If data-testid exists, ALWAYS use it.

Never replace data-testid with XPath.

### Rule 7
Generate strict unique locators.

The locator must identify exactly one element.

### Rule 8
Avoid dynamic attributes

Do NOT use

id generated at runtime
class names generated by CSS frameworks
React ids
Angular ids
UUIDs
timestamps

### Rule 9
Never use nth() unless absolutely required.

Instead identify using parent hierarchy.

### Rule 10
When locating inside tables:

Find row first.

Then child.

Example

page
    .getByRole('row', { name: /Invoice-1001/ })
    .getByRole('button', { name: 'Edit' })

### Rule 11
When locating inside dialogs:

dialog.getByRole()

Never search entire page.

### Rule 12
For dropdowns

Use

getByRole("combobox")

or

getByRole("option")

### Rule 13
For checkboxes

Use

getByRole("checkbox")

### Rule 14
For radio buttons

Use

getByRole("radio")

### Rule 15
For links

Use

getByRole("link")

### Rule 16
For buttons

Always prefer

getByRole("button")

Never XPath.

### Rule 17
For forms

Prefer

getByLabel()

instead of XPath.

### Rule 18
Never use contains(text()) if Role or Label exists.

### Rule 19
Every locator must be readable.

A developer should understand it immediately.

### Rule 20
If no stable locator exists, recommend adding a data-testid attribute.

Example:

Developer Recommendation:

<button data-testid="invoice-submit">

Then use

page.getByTestId("invoice-submit")

## Output Format

Whenever asked to generate a locator:

1. Explain why the locator was selected.
2. Provide the Playwright locator.
3. Mention if a better locator (data-testid) should be added.
4. If the locator is unstable, explain why.
5. Never return Absolute XPath.

## Coding Style

Always return Playwright TypeScript.

Use

readonly locatorName = this.page.getByRole(...);

inside Page Objects.

Never use raw XPath unless absolutely unavoidable.

Prefer readability over shortness.

Follow enterprise automation framework standards.

## Review checklist (before merge)

- [ ] Element confirmed in Playwright MCP or browser snapshot
- [ ] Locator scoped (not global `page.locator('button')`)
- [ ] No duplicate hidden-node matches (strict mode safe)
- [ ] Change limited to `pageObjects/**`
- [ ] No absolute XPath; no index XPath; `nth()` justified if used
